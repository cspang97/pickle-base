# Pickle_Base 워크스페이스 v1

구글 드라이브의 **Pickle_Base** 폴더를 기반으로 일과 지식을 관리하는 개인용 워크스페이스입니다.
단순 파일 탐색기가 아니라, 태스크·스킬의 상태와 결과물(원고·리서치·앱·습관)을 한 화면에서 봅니다.

- 배포: https://cspang97.github.io/pickle-base/ (GitHub Pages · `main` 브랜치 루트)
- 구성: 정적 HTML/CSS/JS (프레임워크·빌드 없음)

## 태스크 기준 집계

상단 필터와 대시보드의 `전체 · 완료 · 진행중 · 미정`은 폴더나 파일 개수가 아니라
`01_업무자동화목록/업무자동화 목록` 문서의 **태스크 블록**만 셉니다.

```
태스크: 태스크 이름
분류: 네이버블로그 | 리서치 | 애플리케이션 | 일상생활
상태: 완료 | 진행중 | 미정
연결 스킬: 스킬: ...
결과물 위치: ...
비고: ...
다음 할 일: ...
```

- 라벨 이름은 바꾸지 않는 규칙이고, 블록 하나가 태스크 한 건입니다.
- 폴더·이미지·일반 파일은 태스크로 세지 않습니다(탭·검색에서는 계속 볼 수 있습니다).
- Drive `export?mimeType=text/plain`이 붙이는 BOM·CRLF·목록 표식(`* `)은 무시하고 읽습니다.
- 목록 문서를 못 읽으면 스킬 정의로 대신 집계하고, 화면에 그 사실을 표시합니다.

| 탭 | 내용 |
| --- | --- |

블로그·리서치·앱·일상·특허등록 탭은 화면 맨 위에 그 영역 분류의 태스크만 모은 표를 보여줍니다
(태스크명·분류·상태·연결 스킬·결과물 위치·다음 할 일 — 업무자동화 탭의 태스크 표와 같은 형식).
분류에 태스크가 없으면 빈 표 대신 “이 분류에 등록된 태스크가 없습니다.”를 보여주고, 상단 상태 필터가 그대로 적용됩니다.
태스크 행을 누르면 상세 패널에서 태스크 정보와 목록 문서 링크를 엽니다.

검색창 아래 상태 필터 칩(`전체 · 완료 · 진행중 · 미정`)의 숫자는 **지금 보고 있는 탭 기준**입니다.

| 화면 | 칩이 세는 범위 |
| --- | --- |
| 대시보드 · 업무자동화 | 전체 태스크 (예: 3 · 2 · 1 · 0) |
| 블로그 | 분류 네이버블로그 태스크 (예: 1 · 1 · 0 · 0) |
| 리서치 | 분류 리서치 태스크 (예: 0 · 0 · 0 · 0) |
| 앱 | 분류 애플리케이션 태스크 (예: 1 · 1 · 0 · 0) |
| 일상·습관 | 분류 일상생활 태스크 (예: 1 · 0 · 1 · 0) |
| 특허등록 | 분류 특허등록 태스크 (예: 1 · 0 · 0 · 1) |
| 통합 검색(검색어 입력) | 검색어에 걸린 태스크 |

대시보드에는 태스크 표를 두지 않습니다(업무자동화 탭의 표와 겹치므로). 대신 분류별 숫자 요약만 보여주고,
표가 필요하면 카드의 “업무자동화 탭에서 표 보기”로 이동합니다.

상단 검색창에서 키워드(태스크·제목·요약·경로·태그)와 상태(완료/진행중/미정)를 함께 필터링할 수 있습니다.
상세 패널에서 문서 요약과 드라이브·블로그 링크를 바로 엽니다.

## 일상·습관 (실적 시트 연동)

`05_일상생활/건강습관 일일실적` Google Sheet를 그대로 읽어 카테고리별 실적을 보여줍니다.

- **일상·습관 탭**: 지금 관리하는 체크리스트 **카테고리 카드** — 항목 수, 최근 달성률, 기록 일수/평균/연속 기록, 최근 기록일의 달성 수.
- **카테고리 클릭 → 상세**: 주소가 `#daily/habit/health`로 바뀌고 히스토리에 쌓입니다(뒤로가기·새로고침·링크 공유 모두 동작).
  1. **인사이트(상단)**: 가장 잘 지키는 항목 / 가장 자주 빠지는 항목과 그 메모 근거 / 직전 기록 대비 추이 / 주말·평일 비교 / 메모 속 음식 패턴 / 다음 실천 팁. 기록이 3일 미만이면 “경향으로만 봐 주세요”를 함께 표시합니다.
  2. **항목별 달성률**: 항목마다 O 일수 / 기록 일수와 막대.
  3. **일 단위 실적**: 최신순 날짜 카드마다 항목별 O/X 칩과 달성 수(`3/4`), 메모.
- 시트 형식(첫 줄이 헤더, 한 줄 = 하루):

```
날짜,요일,통곡물 선택,채단탄 순서,식후 산책,액상과당·단순당 멀리하기,달성 수,메모
2026-11-21,토,X,X,O,O,2/4,빵 섭취로 통곡물·채단탄 미실천
2026-11-22,일,X,O,O,O,3/4,햄버거 섭취로 통곡물 미실천
```

- 날짜·요일·달성 수·메모 외의 칸은 모두 **항목**으로 읽습니다. O/X는 `O o ○ ㅇ Y true 1` / `X x × N false 0`을 받습니다.
- `export?mimeType=text/csv`로 읽고, 따옴표·쉼표·줄바꿈이 든 메모도 안전하게 나눕니다(BOM·CRLF 처리).
- 드라이브 미연결(프리뷰)·시트 없음·읽기 실패·기록 없음은 각각 다른 안내로 처리하고 앱이 깨지지 않습니다.
- 앱은 **읽기 전용**입니다. 여기서 시트에 쓰지 않습니다(기록은 매일 아침 습관 체크에서 시트에 남깁니다).

## 리서치 (요약노트 회차 연동)

`03_리서치/요약노트/4대 AI 신규 기능 리서치` Google 문서를 읽어 주제별 회차를 보여줍니다.

- **리서치 탭**: 영역 태스크 현황 아래에 **리서치 주제 카드**(누적 회차·최근 업데이트·최신 회차 핵심 인사이트)와 그 아래 **회차별 카드**가 최신순으로 붙습니다.
  - 회차 카드에는 회차 번호·날짜·최신 태그, 그 회차의 신규 기능/인사이트/부록(제조 AX 사례·후보 풀·추천) 건수, 핵심 인사이트 1~2줄이 나옵니다.
  - 회차 카드를 누르면 상세가 그 회차로 열립니다(핵심 인사이트 카드가 그 회차 기준으로 바뀌고, 해당 회차 카드가 강조·자동 스크롤).
- **주제 카드 클릭 → 상세**: 주소가 `#research/report/ai-4`로 바뀌고 히스토리에 쌓입니다(뒤로가기·새로고침·링크 공유 모두 동작).
  1. **최신 회차 핵심 인사이트** 강조 카드(문서의 `### 핵심 인사이트`).
  2. **회차별(최신순) 4대 AI 신규 기능** — Claude·ChatGPT·Gemini·Grok 묶음마다 날짜·이름·설명·원문 링크.
  3. 회차마다 **출처 접기**(`### 출처`, 날짜·발행처·링크).
- 문서 형식(회차를 더할 때 같은 구조로 아래에 붙입니다):

```
## 1회차 · 2026-11-23
### 핵심 인사이트
- 제목 — 설명
### Claude
- 2026-11-10 · 기능 이름 — 설명 | https://...
### ChatGPT / ### Gemini / ### Grok
### 출처
- 2026-11-10 · 발행처 — 제목 | https://...
```

- `export?mimeType=text/plain`으로 읽고 BOM·CRLF·`* ` 목록 표식을 무시합니다. 굵게 표시한 소제목(`**Claude**`)도 받습니다.
- 드라이브 미연결(프리뷰)·문서 없음·읽기 실패·회차 없음은 각각 다른 안내로 처리하고, 문서가 없을 때 프리뷰 회차를 섞지 않습니다.
- 앱은 **읽기 전용**입니다. 회차는 문서에 적고 앱은 그것을 읽습니다.

## 특허등록 (v30)

맨 마지막 `특허등록` 탭은 **아이디어가 아직 없는 상태의 틀**입니다. 개인 직접 전자출원(특허로) 기준 4단계를 고정해 두고,
자료가 쌓이면 단계별로 상태가 바뀝니다.

1. **아이디어 발상 · 본업 무관성 확인** — `07_특허등록/01_아이디어`
2. **KIPRIS 선행기술 조사 · 차별점 도출** — `07_특허등록/02_선행기술조사`
3. **명세서 · 청구항 · 도면 초안 구조화** — `07_특허등록/03_명세서`
4. **특허로 전자출원 준비** — `07_특허등록/04_출원`

- 각 단계 카드는 그 폴더의 문서 수를 읽어 `대기` / `자료 N건`으로 표시하고, 자료가 없는 첫 단계에 `다음` 표시가 붙습니다.
- `등록된 아이디어`는 `01_아이디어` 폴더의 문서를 보여주고, 없으면 빈 상태 안내를 유지합니다.
- 연결 스킬은 `01_업무자동화목록/스킬/스킬: 특허등록` 문서에서 실행 조건·결과물·마지막 실행·다음을 읽습니다.
- 작업 목록 문서의 분류에 `특허등록`이 추가되어, 대시보드 분류별 태스크와 업무자동화 탭 필터에도 함께 잡힙니다.

## 2) Google Drive 실시간 연동

자신의 Google Cloud에서 OAuth 클라이언트 ID 하나를 만들어 넣으면, 브라우저가 내 드라이브의 `Pickle_Base` 폴더와 Google 문서를 직접 읽어옵니다.

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트 생성 → **Google Drive API** 사용 설정
2. **OAuth 동의 화면** 구성(외부, 테스트 사용자에 본인 계정 추가)
3. **사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 웹 애플리케이션**
4. **승인된 JavaScript 출처**에 추가
   - `https://cspang97.github.io`
   - (로컬 테스트 시) `http://localhost:8000`
5. 발급된 클라이언트 ID를 앱의 **설정(⚙) → OAuth 클라이언트 ID**에 붙여 넣고 저장 → 상단 **Google 계정 연결**

- 요청 범위: `https://www.googleapis.com/auth/drive.readonly` (읽기 전용, 드라이브에 쓰지 않음)
- 액세스 토큰은 만료 시각과 함께 **이 브라우저(localStorage, `pb.token.v1`)에만** 둡니다. 그래서 새로고침·뒤로가기·다시 열기에서도 다시 로그인하지 않습니다. 만료 60초 전부터는 만료로 보고 버리고, 401 응답이 오면 즉시 삭제합니다.
- 상단 **연결 해제**를 누르면 저장된 토큰을 바로 지우고 구글 쪽 토큰도 폐기합니다. 설정의 “설정·습관 기록 초기화”도 토큰을 함께 지웁니다.
- 폴더는 이름 `Pickle_Base`로 찾고, 설정에서 폴더 ID를 직접 지정할 수도 있습니다.
- 연결된 화면의 문서별 상태 표시는 문서 본문에서 자동 판정한 값입니다(원고는 발행 URL 유무, 스킬은 실행 기록 유무). 태스크 집계는 이와 별개로 `업무자동화 목록`의 상태 라벨만 따릅니다.

## 모바일 뒤로가기 (히스토리)

탭 전환·상세 드로어·설정 모달이 브라우저 히스토리에 쌓입니다.

- 탭을 누르면 주소가 `#blog`, `#hub`처럼 바뀌고 히스토리에 한 칸 쌓입니다. 새로고침·링크 공유에서도 같은 탭이 열립니다.
- 뒤로가기는 앱 밖으로 나가기 전에 먼저 앱 안에서 움직입니다 — 열린 드로어/모달을 닫고, 그다음 이전 탭으로 돌아갑니다.
- 드로어 주소는 `#hub/task/2`, `#blog/item/<파일 ID>`처럼 남습니다. ✕·바깥 클릭·Esc로 닫으면 그 히스토리 항목을 되감아, 뒤로가기가 같은 화면을 한 번 더 보여주지 않습니다.
- 첫 화면에서 한 번 더 뒤로가기를 누르면 원래대로 사이트를 벗어납니다.

## 3) 화면 잠금

GitHub Pages 주소는 공개이므로, 설정에서 PIN 잠금(선택)을 켤 수 있습니다.
이 잠금은 화면을 가리는 용도이며 실제 보안 장치가 아닙니다. 자료 보호는 드라이브의 Google 로그인과 권한이 담당합니다.

## 파일

```
index.html                화면 골격
assets/css/app.css        스타일(라이트/다크, 반응형)
assets/js/habit-data.js   실적 CSV 파싱 · 일 단위 집계 · 인사이트
assets/js/research-data.js 리서치 요약노트(회차·인사이트·4대 AI 항목·출처) 파싱
assets/js/preview-data.js 프리뷰 스냅샷(실적 시트 2일 · 리서치 1회차 포함)
assets/js/drive.js        Google Identity Services + Drive API v3 연동, 토큰 보관(localStorage)
assets/js/app.js          화면 렌더링·검색·필터·일상·습관 상세·리서치 회차 상세·설정·히스토리(뒤로가기)
```
